# Game: E1M1 / E1M2 测试候选版

## 当前范围

这是 SkyOS 内的原生精简规则版本，使用 Freedoom 0.13.0 的 E1M1、E1M2 地图与素材。两关共用逻辑和渲染；不要求在计算器上解析完整 IWAD。

- 35 Hz 逻辑；两关实际起点、完整线段和 BSP sector 查询。
- 蓝、红、黄钥匙，锁门、升降台、移动地板、出口、秘密与伤害地面。
- 四类怪物和 Spectre；有唤醒、追逐、攻击、受伤、死亡、尸体与碰撞。
- 216 张只读 4 位灰度素材：四类怪物的八方向行走／攻击／受击、死亡动画、钥匙、弹药、武器和其他拾取，共 125,921 字节像素；包含灵魂球、狂暴与背包。
- 保留经典底栏、头像、手枪与霰弹枪动画；显示当前武器弹药、护甲、三色钥匙与真实弹药容量。
- 世界材质候选：198 张墙面和 87 张地面／天花板，使用地图实际的上下／中间纹理、偏移和门对齐；透明栏杆的孔洞保留后方墙与怪物。
- E1M1 通关后进入 E1M2；死亡可重试，E1M2 通关可重玩。

当前源码支持手枪与霰弹枪；其他武器与弹药拾取会保存库存，但尚无对应攻击。怪物 AI、伤害和攻击时序仍为近似规则，声音和投射物尚未接入。八方向素材的上一版已刷入，用户确认显示朝向准确；本轮霰弹枪与 Test 应用候选尚未刷入，实机测试按用户要求留到统一验证。地面／天花板目前以玩家所在 sector 进行透视采样，平台深度遮挡已接入；相邻 sector 的独立平面着色和完整 Doom visplanes 尚未实现。

## 操作

| 键 | 功能 |
|---|---|
| 上 / 下 | 前进 / 后退 |
| 左 / 右 | 较慢转向 |
| F1 | 单次射击 |
| F2 | 使用门 / 开关；通关后下一关或重玩；死亡后重试 |
| F3 | C1 明亮、C2 默认、C3 较强对比度 |
| F4 | 场景中切换已拥有的手枪 / 霰弹枪；地图中切换全图 / 跟随缩放 |
| F5 | 场景 / 地图 |
| F6 / ON | 退出到应用列表 |

底栏数字保持深色字和浅色背景。三色钥匙另用 B/R/Y 字母区分，避免灰度屏无法辨色；关卡／对比度／地图缩放和短时事件文字均移入底栏。3D 与地图共用 y=0..100 的场景，底部 26 行为状态栏；最上方硬件电池指示符条仍由 Loader 独立控制。

必要的墙面开关显示 F2 小牌，触发后显示 OK；出口有 EXIT 标记。地图上的 D / S / X 分别标出手动门、远端开关与出口；走过触发的线不会伪装成 F2 开关。

## 平地 Test 与霰弹枪候选

默认应用列表改为 `KhiCAS / Notes / Game / Test`。旧 Lite 的入口、任务与旧网格资源不再链接进默认固件；`doom_lite` 目录名继续保留，因为 Game 仍使用其中的共用逻辑、渲染与 HUD。旧射线实现仅保留在主机对照检查与显式 legacy 构建中。

`Test` 在独立的平地封闭房间运行，不替换 E1M1 / E1M2。场景与 Game 共用世界材质、精灵、武器、HUD 和退出路径，没有第二份完整像素库或额外 LCD 帧缓冲。F2 循环以下三个预设；死亡时 F2 重试当前预设。F1 / F3 / F4 / F5 / F6 与 Game 相同。

| 预设 | 内容 |
|---|---|
| SPRITES | 四类怪物的八方向、行走、攻击、受击、死亡与尸体循环；演员不伤害玩家、不阻挡移动；直接拥有手枪和霰弹枪 |
| COMBAT | 四类正常 AI 怪物与真实战斗；可测试射击、伤害、击杀、死亡重试及拾取 |
| ITEMS | 移除怪物，展示十二个拾取物，包括霰弹枪、弹药、三色钥匙与补给 |

霰弹枪消耗一枚 shell，固定七条射线各造成 10 点伤害，动画与冷却各 35 tic。弹丸和射速是本项目的精简规则，未声称复刻原版随机伤害。F4 在动画结束时才能切换，冷却不会通过切枪清零；E1M1 到 E1M2 保留当前武器与库存。底栏大数字随当前武器显示 bullets 或 shells，PIS / SG 标签保持可见。

新增六张霰弹枪回弹、装填与闪光图，共 39 张 UI patch、17,062 字节像素；闪光只提高武器区域对比度。文字继续使用浅背景与深色字，短消息限制在事件区域，不覆盖武器标签或数值。六种武器拾取物已补上可见素材。

ARM 镜像核对：Game 状态 7,224 字节、渲染工作区 49,857 字节、世界只读载荷 218,204 字节、精灵只读载荷 130,453 字节、UI 只读载荷 17,846 字节、Test 地图与预设名称 1,871 字节。世界载荷包含 Test 的 88 字节材质引用表；以上资源不能当作全部 RAM 占用。默认 BSS 仍为 86,064 字节。签名 System 镜像为 5,910,140 字节，容量检查通过。

测试目录为 `build/game-test-app-validation/`，76 项 Python 测试及总共 39 个编译／检查阶段全部通过。新增检查覆盖七弹丸／墙后遮挡、切枪和冷却、库存保留、Test 的 5,841 个位置／BSP 外部查询、1,024 tic 四面墙碰撞、所有朝向的封闭房间射线、612 帧武器／对比度／预设组合，以及每个霰弹枪动画 tic 的绘制边界。三个 Test 预设另各运行 512 帧工作量基准，没有池溢出或渲染降级。修正了逻辑 tic 之间快速释放／重按可能漏掉新边沿的问题。主机计时不代表计算器帧率；实际按键、分页耗时与重复退出稳定性仍需刷入后统一测试。

`DOOMG_BOOT / PERF / EVENT` 记录 Test 预设、当前武器、当前弹药、shells 和霰弹枪冷却。SPRITES 的预览动画另外记录 `preview_total_us / preview_max_us / preview_calls`，该耗时已包含在逻辑总量中，不能重复相加。调试面板支持这些字段及 UI / Test 只读容量，并继续兼容上一版设备日志。

## 离线验证与已修问题

自动检查入口：

```powershell
python tools/doom/run_game_checks.py --cc D:/w64devkit/bin/gcc.exe
```

需要本机 C 编译器与用于资源复现检查的原始 `freedoom1.wad`。默认素材位置是仓库旁的 `Freedoom-research/extracted/freedoom-0.13.0/`，生成器核对原始文件 SHA256。构建固件本身只用已生成的表。

- 地图损坏数据、16 位索引、BSP、稀疏 cell/line 引用与只读数据检查。
- E1M1 → `NextMap` → E1M2 连续路径回放：8,478 次真实 `Step`、33 次 F2，三色钥匙与出口均完成。
- 路径回放只设置无敌计时和朝向，位置、门、平台、拾取与完成状态均由游戏接口更新；保留 29 / 93 个怪物与真实弹药，必要时用 F1 清除挡路怪物。此检查证明通路可推进，战斗伤害另行测试。
- 73,081 条 LOS 与全 linedef 精确参考对照，涵盖格角、端点与三套 sector 高度。
- 481 个场景 / 地图 / 动画 / 开关画面的缓冲区边界检查；768 条射线与全线段参考对照。
- 保留旧 Lite 主机对照的 12,288 条射线、96 个视角回归；UI 动画与屏幕边界回归。
- 固定池、长时逻辑、关卡重置、拾取、钥匙、特殊线和出口检查。

初始两关版本的统一运行包含 47 项 Python 测试和所有 C 检查；每个编译 / 运行阶段均成功。481 帧渲染回归没有触发容量降级。初始版本的人工近怪物压力相机不保证在合法区域，E1M1 的 512 帧记录到 42 条射线的安全降级、累计 828 个射线行；这些次数与面积保留在旧日志，不能据此声称任意视点都完整绘制。后续世界材质和八方向版本的检查数量与缓存结果见下节。

此次审查修正了红钥匙在高台上无法从旁拾取、玩家穿过活怪物、格角漏墙的穿墙射击、Berserk 降低已有高生命、背包容量显示过时，以及底栏最后一行数字裁切。还修正了窄通道身体与墙相切被拒绝、跨格角移动遗漏特殊线触发、升降台边缘夹人，以及关闭的门忽略跨边界身体等问题。

钥匙的拾取高度与特殊线语义对照了仓库现有 Doom 移植代码，以及 id Software 的 [拾取逻辑](https://github.com/id-Software/DOOM/blob/master/linuxdoom-1.10/p_inter.c) 和 [特殊线逻辑](https://github.com/id-Software/DOOM/blob/master/linuxdoom-1.10/p_spec.c)。社区内存布局研究见 [Doom 社区研究](doom-community-expansion.md)；地图预处理细节见 [地图审计](doom-game-maps.json)、[路线必要条件审计](doom-game-route-audit.json)。静态可达图不等于完整游戏通关证明。

## 性能与内存

持续保留 32 帧一批的微秒日志：

- `DOOMG_PERF`：逻辑、场景、精灵、武器、HUD、LCD、帧间隔的总量和峰值，以及丢失的 tic。
- `DOOMG_DETAIL`：AI、动画、门 / 平台、碰撞、LOS 的总量、峰值和调用次数；射线、cell、边界测试、绘制跨度、精灵像素和降级面积。
- 世界材质日志增加互不重叠的 `ray_total_us` / `plane_total_us` / `wall_total_us` 与各自峰值；每帧墙面／平面采样量也随批次保存。阶段边界计时没有进入像素循环。
- `DOOMG_BOOT`：任务启动、关卡初始化 / 切换耗时及固定状态 / 渲染缓存字节数。
- `DOOMG_EVENT` / `DOOMG_EXIT`：交互与退出过程。

AI 包含其内部的碰撞和 LOS，这些分项有重叠，不能把它们相加当作总逻辑耗时。面板显示每 tic 平均与单次峰值。固定 BSS 与借用的 LCD 帧缓冲不属于 `malloc` 曲线，另显示固定容量与池峰值。

优化保留固定容量：128 个 actor、64 个 mover、每 tic 最多处理 8 个 AI；地图只读，tag / 邻居 / line 索引在电脑上预处理。动画直接读取打包像素，没有逐帧解码堆；对比度不额外复制帧缓冲。初始两关版本使用 12 段射线缓存（9,344 字节）；后续世界材质／平台遮挡版的缓存见下节。超限会记录次数和填充面积。

主机基准含出生点全向转动、怪物附近人工压力视点、全图与旧 E1M1 场景对照。主机计时只能比较代码工作量，不能证明 ARM 帧率、NAND 页面缓存行为、LCD 耗时或实机退出稳定性。后续世界材质版的实测与用户优先级见下节；主机结果不作为帧率承诺。

同一份游戏状态和 HUD 下，三轮交替对比逐行跨度扫描与直接写入 framebuffer 的 8 行分块绘制，四个场景的画面校验值一致：

| 主机场景 | 逐行绘制均值 | 分块绘制均值 | 场景耗时降幅 |
|---|---:|---:|---:|
| E1M1 出生点转向 | 70.683 µs | 57.882 µs | 18.11% |
| E1M1 怪物附近压力 | 79.971 µs | 65.098 µs | 18.60% |
| E1M2 出生点转向 | 64.887 µs | 53.896 µs | 16.94% |
| E1M2 怪物附近压力 | 59.739 µs | 51.560 µs | 13.69% |

轴对齐边界与 DDA 复用每条射线的倒数，余数修正保留精确距离；门纹理坐标只在选中门表面后计算。146,741 组轴交点与原通用相交公式的距离 / 门坐标逐值一致。ARM `-Os -fstack-usage` 隔离编译中，新场景函数为 232 字节、精灵函数为 504 字节；这是单函数用量，尚无实机总栈峰值。

初始两关版本的 ARM 编译与镜像容量检查通过：System 镜像 5,598,316 字节；ELF 的 text / data / BSS 为 5,588,865 / 4,948 / 45,584 字节。Game 状态为 7,220 字节，渲染可写状态为 9,381 字节（跨度缓存外还包含计数器与标志），均不代表系统的总 RAM 占用。

完整检查日志与计时在 `build/game-validation/checks.json` 及同目录各项 `.log`。最终固件、SHA256、ARM 段大小和测试摘要另保存到工作目录外的测试包。

## 回来后的实机检查

### 世界材质后续候选

`build_game_world.py` 使用相同的固定 SHA256 Freedoom IWAD，在电脑上复合、缩小、提亮并增强局部细节。每张 32×32 材质仅 512 字节，保留原材质世界尺寸（包括非二次幂尺寸）与 sidedef 偏移。原始 287 个名称去重后生成 285 份像素；完整只读对象载荷为 ARM 218,116 字节，另有编译对齐。闭合高台的上下材质分别绘制；门的纹理随 ceiling 移动，不因屏幕裁切重新拉伸。

墙面每两列共享射线、每行保持独立采样。地面／天花板使用 2×2 屏幕采样和 256 字节行缓存，并收窄大面积平面的灰度范围，避免黑色地面淹没怪物。C1 / C2 / C3 保留。新增只读分页读取必须重新实测 FPS；主机基准不能保证实机 10 FPS。

已复现并修复 E1M1 高台地面漏出下层怪物：玩家 `(1456,-224)` 时，关闭地面遮挡会露出 56 个怪物像素，修复后为 0；靠近边缘 `(1312,-224)` 时，真实栏杆孔洞中仍有 37 个可见像素，未把正常俯瞰一并屏蔽。地面／天花板沿 sector 边界生成深度遮挡分段，天空不作为不透明天花板。平面着色仍使用当前 sector 的背景，未实现完整的 Doom visplanes。

深度遮挡需要额外分段，固定缓存改为每条射线 32 段，4096 段总池与每条射线的起点／计数占 49,536 字节。ARM 渲染可写工作区共 49,857 字节（约 48.7 KiB），比初始两关版本增加 40,476 字节；没有运行时扩容或解码纹理堆。有效分段每帧连续存放，未用尾部不触碰，减少 40 KiB VRAM 缓存承受的热页面；这不会缩小预留 BSS。日志另外保存有效跨度字节数的均值与峰值。481 帧渲染矩阵、两关各 256 个合法出生点朝向、平台视点及 512 帧基准采样均未触发容量降级，这只证明已测视点。

容量已满时仍会保留不透明的降级覆盖，保护后方精灵遮挡。定向检查填满缓存并分别让最后一段为地面或透明栏杆，验证近处表面保留、后方演员遮住、前方演员可见，且面积日志对应实际覆盖。

完整检查含 61 项 Python 测试、贴图复现、透明栏杆、纹理坐标、平台、地图顶行、玩法／退出和缓冲区边界，共 29 个成功阶段；最终 ARM 镜像为 5,819,124 字节，text / data / BSS 为 5,809,678 / 4,948 / 86,064 字节。一次主机基准中，E1M1 出生点场景从旧版 65.705 µs 增至 104.898 µs，E1M2 为 89.115 µs；真实纹理、平台遮挡与分阶段计时有额外工作，不能用这些主机时间推算 ARM FPS。有效分段池在 E1M1 出生点平均 8,002 字节，采样峰值 23,880 字节；连续池与原布局的 33 张图像、7 个 512 帧场景校验完全一致。完整细分数据保存在测试包中。

材质复现、复合损坏输入、灰度／透明、U/V 对齐、高台材质、栏杆孔洞、地图顶行和帧外边界检查随统一 runner 运行。世界材质版的离线测试目录为 `build/game-world-validation/`；资源审计在 [世界材质审计](doom-game-world.json)。前一个两关版本采样约 14 FPS；此数据不代表新材质版。

先刷候选 System 镜像，核对 C1 / C2 / C3、地图与动画。随后实走升降台和三色钥匙路线，验证进入 E1M2、死亡重试，以及移动 / 开枪时退出。两个关卡分别记录出生点与交战场景的 PERF / DETAIL；真实 LCD 和分页开销出现后再决定是否降低射线数量或绘制细节。

已验证的经典 UI 固件保留作回退。初始两关候选在断开设备期间准备，后来已完成 System 刷写，用户确认 E1M1 场景与经典底栏正常；串口记录了移动／战斗以及退出到 task_delete。E1M2 实机通关尚未验证。

2026-10-03 世界材质／平台遮挡版已刷入，镜像 SHA256 为 `5D146E7C45264FD9FD1B89E66F102EB7148B6700809159BB11B8444D9158D072`。刷写工具 exit 0，8 个输出校验样本匹配；没有独立 NAND 回读校验。串口确认世界资源 218,116 字节、渲染状态 49,857 字节，并记录到正常退出的 `task_delete`。用户报告画面流畅、基本清楚；平台透地实机复测仍待反馈。
